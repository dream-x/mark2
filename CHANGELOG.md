# Changelog

История изменений в формате «что сделано → к чему привело». Эффекты — из
бенча (`bench/results/`) и живых прогонов, не из ощущений. Реестр причин
каждого контроля — в [docs/decisions.md](docs/decisions.md).

## 2026-11-04

### Контроль процесса: write-churn сенсор, коэрция аргументов, абляция
- **Write-churn сенсор** (`[agent] write_churn`): нудж на 3-й подряд записи в
  один файл без единого запуска между ними, жёсткий — на 6-й.
  ← Пилот t17-v1: flint:40b переписал test_chat.py ~10 раз подряд вслепую,
  qwen3.6 — тот же паттерн; существующий детектор зацикливания этого не видит
  (вызовы не идентичны). → Эффект меряется абляцией t17-v3 (ожидается).
- **Коэрция числовых строк** в аргументах тулов (`[agent] arg_coercion`,
  счётчик `coerced N` в статистике): `"60.0"` → 60 без потерь, мусор
  по-прежнему отбивается. ← flint и qwen3.6 стабильно шлют числа строками,
  десятки отбитых вызовов за сессию (flint на T17: tool error rate 33%).
  → Попутно найден баг ядра: число `60.0` проходило JSON Schema, но роняло
  десериализацию в u64.
- **`--agent-override 'key = value'`** в ранере: абляционные прогоны
  (той же матрицей с выключенной фичей), overrides пишутся в results.json и
  шапку отчёта. ← Методология: менять одну часть харнеса за раз и измерять
  вклад каждой; бенч — телеметрия обвязки.
- **`edit_strategy` per-model в матрице**: flint40 → whole_file.
  ← На длинных сессиях flint роняет поля search/replace-edit и спасается
  только перезаписью целиком (наблюдение T17 и чат-демо).

### Z.ai (GLM) в матрице — ноль строк кода
- glm-5.3 / glm-5.3-flash / glm-5.2 через Coding Plan: `base_url` +
  `api_key_env = "ZAI_API_KEY"` в models.toml. Полный агентный цикл (write →
  read → ответ) прошёл с первого запуска, их prompt-кэш работает.
  ← Поддержка ключей (`api_key_env` в конфиге, CLI и матрице) заложена в
  фазе 1 «на вырост». → Архитектурное решение окупилось: новый провайдер =
  три записи в TOML. glm-5.3-flashx в план не входит (HTTP 1311).

### Окружение бенча: uitest_env (61044b2)
- Задаче с `uitest_env = true` ранер даёт PATH с единственным `python3` —
  обёрткой над интерпретатором bench/uitest/.venv (aiohttp+playwright);
  pip и прочие бинари venv модели не видны; окружение собирается до первой
  модели. ← Пилот t17-v1: qwen36c сделал 14 ходов за час — всё время ушло на
  `pip install aiohttp` через задушенную параллельными загрузками сеть.
  → Модель тратит ходы на задачу, а не на обустройство питона. Находка:
  симлинк на venv-python не работает (python ищет pyvenv.cfg рядом с путём
  запуска) — только shim-обёртка.

### Проектный тир T17-ws-chat (08d5ec5)
- Задача «построй чат на вебсокетах + собственный автотест», verify в три
  слоя: A — протокол ws-клиентами, B — headless Chromium водит страницу как
  пользователь, C — `python3 test_chat.py` модели. Самопроверка: golden
  PASS, фикстура со вчерашним багом flint валится ровно слоем B.
  ← Живое демо 2026-11-03: скриптовый тест протокола был зелёным при
  неюзабельном UI (авто-джойн как anon с задизейбленными контролами) — баг
  нашёлся только руками в браузере.
  → Пилот t17-v1 — 0/5, и это сигнал задачи, а не шума: beam прошёл A+B
  (рабочий чат за 194с), все три ипостаси qwen36c (Metal q4 / CUDA q4 /
  MLX fp4) упали одним и тем же багом до буквы (temp 0 детерминирует
  семантику, квант и железо меняют только скорость), flint снова сломал UI
  при зелёном протоколе. Слой C — 0/5: ни одна модель не написала рабочий
  собственный тест. Дисциплина самопроверки — главное слабое место локальных
  моделей; ранер получил per-task `max_turns` и `verify_timeout_seconds`.

### Эксперимент «квант × железо» (qwen3.6:35b-a3b-coding, MoE 35B-A3B)
- Генерация: q4@5090 — 388 tok/s, q4@Mac — 106, MLX-fp4@Mac — 114,
  bf16@Mac — 54, mxfp8@Mac — 53. Префилл 10.7k токенов: 5090 — 4529 tok/s,
  Mac — ~1550 (q4/bf16), mxfp8 — 925.
  → 5090 быстрее Mac в 3.6×/2.9× (генерация/префилл); полная точность стоит
  2× скорости; mxfp8 на Metal бесполезен (скорость bf16 при вдвое меньшем
  весе — ядра не оптимизированы); MLX-пайплайн ollama пока не годится для
  агентных сессий (14 ходов/час на T17 против 34 ходов за 8.5 мин у той же
  модели на 5090). Качество по квантам — ночной прогон hard-тира (ожидается).

## 2026-11-03

### Компакция в бою и ReadOnly-восстановление (fc4b072, T15/T16)
- Проактивная компакция перенесена внутрь sample_loop (проверка порога на
  каждой итерации, шторм-защита по свежему Usage), per-task `policy` и
  `context_limit` в бенче. ← Подготовка T15 вскрыла дыру ДО прогона: порог
  проверялся только в начале хода, в `-p` — никогда; ollama молча обрезала
  промпт. → Ctx-v1 24/30: компакция сработала у всех 5 моделей в каждом
  прогоне T15 (bolt4 при этом теряет факты при суммаризации — 0/3), T16
  показал instruction-following-провал qwen27 (ответ верный, но процитировал
  приманку в запрещённой форме).

### Hard-тир T09–T14 (5876c76)
- Шесть задач в известные слабые места: неоднозначный edit (1457 строк),
  байт-в-байт YAML, каскад из 3 багов, приманки в доках, перенесённый
  конфиг, точный CSV. Все — с adversarial-самопроверкой (golden/untouched/
  мутанты). ← Базовые T01–T08 матрица v2 прошла 119/120 — бенч перестал
  различать модели. → Hard-v1 77/90: flint40 и qwen27 100%, qwen9 94%,
  bolt4 39% — тир дискриминирует; 4B рассыпается на точности, не на
  понимании. Итоговая таблица в README: flint40 48/48 — выбор модели для
  реальных задач стал решением по данным.

### Живое демо: чат на вебсокетах (flint:40b, вне репо)
- Харнес построил рабочий чат (aiohttp + vanilla JS) за два прогона: первый
  упёрся в max_turns=50 с рабочими файлами, ручное тестирование в браузере
  нашло UX-баг (авто-джойн), второй прогон его починил, поймав собственную
  регрессию. → Родился проектный тир T17 и требование UI-слоя верификации;
  наблюдения «flint роняет схему edit», «timeout_seconds строкой» стали
  фичами харнеса (edit_strategy, коэрция).
