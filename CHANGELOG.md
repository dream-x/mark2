### Аудит безопасности: `write`/`edit` заперты в cwd, подтверждение целиком, env детей без секретов
- `write` и `edit` пишут только внутри cwd: цель резолвится покомпонентно
  (`tools/confine.rs::confine_target` — существующая часть по диску с
  раскрытием симлинков, недостающие подкаталоги простыми именами), итог
  обязан лежать внутри канонизированного cwd, пишется резолвленный путь.
  Абсолютный путь наружу, `..`, симлинк-файл или симлинк-каталог наружу —
  отказ с явным «Path X is outside the working directory … `write` only
  changes files inside the working directory» даже для несуществующего
  пути; висячий симлинк — отказ своим текстом («goes through a symlink
  whose target does not exist») (у `read` там по-прежнему «File not found» —
  различие осознанное, `docs/decisions.md`). Запись в новый подкаталог
  внутри cwd и симлинк внутрь работают как раньше; схемы `path` у
  `write`/`edit` говорят «inside the working directory».
  `approval_prompt` (CLI): ключевое поле — `bash.command` (многострочное —
  блоком), `write`/`edit.path`, `web_fetch.url`, `web_search.query` —

  переписан под новый формат. +22 теста (ядро 372 → 390 и 1 проба под

### Гейт инвертирован: незнакомый тул заперт, свобода — только из allowlist
- `permission::READ_ONLY_TOOLS` (`read`, `grep`) — публичный allowlist:
  `PermissionPolicy::check` пропускает без гейта только его, всё остальное
  в `ask_writes` спрашивает, в `read_only` отклоняет. Тулу вне всех списков
  — свой отказ `unclassified_denial`: «Permission denied: `X` is an
  unclassified tool, and unclassified tools are locked in this read-only
  session…» с перечнем свободных тулов. `MUTATING_TOOLS`/`NETWORK_TOOLS` на
  месте — точные формулировки отказов и разметка промпта. Агентский цикл
  не отдаёт гейту имена вне реестра: галлюцинированный тул, как и раньше,
  получает «Unknown tool … Available tools: …», а не вопрос пользователю о
  несуществующем туле. +6 тестов (ядро 372 → 378).
  ← Аудит безопасности 2026-11-08, High №4: всё незнакомое считалось
  читающим, и тул, добавленный в реестр без строчки в `permission.rs`,
  молча получал свободу в `ask_writes` и в `read_only` (ревьювер
  `scripts/review.sh`).
  → Забытая классификация стоит вопроса или отказа, а не тихой дыры;
  `every_default_registry_tool_is_classified` валится на первом же
  неклассифицированном туле реестра. Для пяти локальных и двух сетевых
  тулов решения политики прежние, промпт и определения тулов не менялись.

### Доводка сетевых тулов по ревью: сбой SearXNG — ошибка, поиск не чаще раза в 2 с
- `web_search`: пустые `results` при непустом `unresponsive_engines` —
  теперь ошибка тула («Search backend problem: no results and N engines did
  not respond (…). Try again later or continue without `web_search`.»), а
  не `Ok` «No results found»; пустые `results` при живых движках — как
  раньше, честное «не найдено». Имена движков (идут вне маркеров
  недоверенных данных) фильтруются по `[a-z0-9 ._-]{1,32}`, остальные
  выбрасываются, не уцелело ни одного — только число. Между двумя

  cwd, симлинки не разыменовываются. Под `read_only` доступен наравне с

### Ревьювер на самом mark2: `scripts/review.sh` (dogfooding)
- Первый агент-пресет поверх ядра — ни одной правки ядра: дифф уходит в

  нумерует строки хунков номерами новой версии файла, повторяет прогон без
  вердикта один раз, режет дифф на 120 КиБ и глушит модель вотчдогом
  (600 с). Офлайн-контракт — 59 проверок под dash/bash/sh с фейковым mark2.
  ← Ревью перед коммитом — гейт, а не агент в цикле (у marmelab авто-ревьювер

  найдены с точной строкой, безобидные диффы — approve без выдуманных
  находок; нумерация строк ускорила off-by-one со 138 до 26 с (out-токенов

### Контроль процесса: write-churn сенсор, коэрция аргументов, абляция
- **Write-churn сенсор** (`[agent] write_churn`): нудж на 3-й подряд записи в
  один файл без единого запуска между ними, жёсткий — на 6-й.
  ← Пилот t17-v1: flint:40b переписал test_chat.py ~10 раз подряд вслепую,
  qwen3.6 — тот же паттерн; существующий детектор зацикливания этого не видит
  (вызовы не идентичны). → Эффект меряется абляцией t17-v3 (ожидается).
- **Коэрция числовых строк** в аргументах тулов (`[agent] arg_coercion`,
  счётчик `coerced N` в статистике): `"60.0"` → 60 без потерь, мусор
  по-прежнему отбивается. ← flint и qwen3.6 стабильно шлют числа строками,
  десятки отбитых вызовов за сессию (flint на T17: tool error rate 33%).
  → Попутно найден баг ядра: число `60.0` проходило JSON Schema, но роняло
  десериализацию в u64.
- **`--agent-override 'key = value'`** в ранере: абляционные прогоны
  (той же матрицей с выключенной фичей), overrides пишутся в results.json и
  шапку отчёта. ← Методология: менять одну часть харнеса за раз и измерять
  вклад каждой; бенч — телеметрия обвязки.
- **`edit_strategy` per-model в матрице**: flint40 → whole_file.
  ← На длинных сессиях flint роняет поля search/replace-edit и спасается
  только перезаписью целиком (наблюдение T17 и чат-демо).
