# Changelog

История изменений в формате «что сделано → к чему привело». Эффекты — из
бенча (`bench/results/`) и живых прогонов, не из ощущений. Реестр причин
каждого контроля — в [docs/decisions.md](docs/decisions.md).

## 2026-11-05

### Post-edit сенсор: харнес сам проверяет правку
- После каждого успешного `write`/`edit` агент запускает
  `[agent] post_edit_command` (`sh -c` в cwd, таймаут
  `post_edit_timeout_seconds` (дефолт 30 с), kill всей группы, вывод —
  первые и последние 2000 байт) и при exit ≠ 0 дописывает секцию
  `post-edit check failed (exit N)` к результату той же записи; exit 0 —
  тишина, даже с выводом (сигнал только об ошибке). Маркер
  `[agent] post_edit: exit N`, колонка `post_edit` в «Обвязке» отчёта
  бенча, ключ `post_edit_command` в task.toml, `--agent-override`
  перекрывает (пустая строка = выключить). Проваленная проверка глушит
  нудж write-churn: модель уже увидела настоящую ошибку.
  ← P1 из e2e-findings «нет контура верификации»: модели правят и не
  перепроверяют либо ищут команду проверки итерациями (flint40 в T17 —
  «зелёный протокол, сломанный UI»; bolt4 — 39% на точных правках
  hard-тира). → По умолчанию выключен: без конфига запросы к модели
  байт-в-байт прежние (закреплено тестом); вклад в pass rate — абляция
  T04/T11 ниже.

### Первые числа тира ревью: glm-5.2 — единственный настоящий ревьювер
- Матрица T20/T21 × {glm52, qwen36c, qwen9, gemma31c} × 3 (review-v2 +
  переигровка glm52 после сетевых отказов Z.ai): glm52 — **6/6** (recall
  3/3, precision 3/3, каждый раз grep → report.py → needs-work с точным
  разбором); qwen36c — 4/6 (ищет всегда, находит 1/3); qwen9 и gemma31c —
  3/6: профиль «на всё approve». gemma, наш гейт больших диффов, валит T20
  за 0.6 с с **нулём тул-коллов** — её approve не означает проверку.
  Живые повторы вчерашних сценариев с новым grep: R5 — qwen36c сменил
  профиль (14 grep + 8 точечных read вместо 4 отбитых bash), но в 600 с
  не сходится, gemma — 1 с и легитимная находка «нет тестов»; D (64 КиБ) —
  qwen36c по-прежнему тонет (кап 600 с), gemma — approve за 2 с не глядя.
  ← «Как повысилось качество после внедрения ревьювера?» — на глаз было
  не ответить. → Ответ числами: grep сместил узкое место qwen3.6 с
  инструментов на экономику рассуждений; approve-гейт на gemma — слабая
  гарантия (ловит формат/очевидное, скрытые от диффа баги — нет); для
  вердикта «по существу» большие диффы стоит отдавать glm-5.2.

## 2026-11-04

### Бенч: тир ревью — T20 (recall) и T21 (precision)
- Две задачи меряют модель в роли ревьювера `scripts/review.sh`: промпт —
  замороженный вывод обёртки (`prompts/review.md` + нумерованный дифф,
  генерится `regen.sh` настоящим review.sh с фейковым mark2), policy
  read-only. T20: дифф переводит `page_bounds()` на полуоткрытый диапазон
  и внутри себя согласован, а сломанный вызыватель `report.py` (каждая
  страница прихватывает строку следующей) виден только поиском — pass =
  needs-work + назван `report.py` + ссылка `lib/pager.py:N` в изменённом
  хунке. T21: поведение-сохраняющий рефакторинг того же проекта — pass =
  approve. Пара читается вместе: «на всё needs-work» и «на всё approve»
  набирают ровно половину.
  ← Качество ревьювера оценивалось на глаз по разовым прогонам; нечем было
  отличить модель, которая ищет вызывателей, от модели, которая судит по
  одному диффу. → Разделение программное: смоук qwen3.5:9b — T20 0/1
  (approve, 0 тул-коллов), T21 1/1; verify проверен на синтетических
  ответах (sh и dash) без расхождений.
- Калибровка T20 по первой матрице (review-v1): verify засчитывает
  «needs-work + назван `report.py`» без требования якоря `lib/pager.py:N`
  в хунке. ← Модели, нашедшие баг, якорили находку на вызывателе
  `report.py:38` — семантически верно, а verify валил (recall по verify
  1/12 при реальном 4/12). → На тех же ответах verify = реальность;
  `report.py` в промпте не встречается (regen гарантирует), так что
  назвать его можно только после поиска.

### `read` заперт внутри cwd — общий замок с `grep`
- `read` читает только внутри рабочей директории: путь канонизируется
  (`..` и симлинки раскрыты) и обязан лежать внутри канонизированного cwd;
  абсолютный путь наружу, `..` и симлинк наружу — ошибка текстом для
  модели, «File not found» — прежним текстом (нет файла ≠ доступ запрещён).
  FIFO и устройства отбиваются, а не вешают ход. Логика — в общем с `grep`
  модуле `tools/confine.rs` (тексты и тесты `grep` не менялись); тест
  `resolves_absolute_paths`, закреплявший дыру, перевёрнут.
  ← Находка ревью 2026-11-04: `read` принимал любой абсолютный путь и
  симлинк наружу, то есть «read-only ревью» (`--policy read-only`) могло
  прочитать любой доступный пользователю файл системы и унести его в
  промпт. → Граница одна на оба читающих тула, +12 тестов, устойчивость
  проверена мутациями (без `starts_with` падают 8, без канонизации cwd —
  21); `write`/`edit` пока без замка — отдельное решение, записано в
  `docs/decisions.md`.

### `--temperature` в CLI; ревью детерминированное по умолчанию
- Флаг `mark2 --temperature <0..2>` — старший слой над `[agent] temperature`
  из конфигов, как `--model`; значение вне диапазона — ошибка clap (exit 2)
  ещё до запроса, а не отказ сервера посреди хода. `scripts/review.sh`
  передаёт `--temperature ${MARK2_REVIEW_TEMPERATURE:-0}`.
  ← Температура давно жила в конфиге (бенч пишет `temperature = 0.0` в
  `.mark2.toml`), но ревьюверу выставить её было нечем — не писать же
  конфиг в чужой репозиторий; вердикты гуляли от прогона к прогону.
  → Ревью идёт на temperature 0 без файлов конфига; test-review.sh —
  68 проверок (+7), в т.ч. что ошибка флага даёт exit 1, а не 2
  (который читался бы как needs-work).

### Тул `grep`: read-only поиск по файлам
- Пятый тул `grep` (`pattern` — regex, `path` — файл или директория внутри
  cwd, `case_insensitive`): построчный рекурсивный поиск, вывод
  `путь:строка: текст`. Скрытое (включая `.git`), бинарные файлы,
  `node_modules` и кэши с `CACHEDIR.TAG` (`target/`) пропускаются; капы —
  200 совпадений, 30 000 байт вывода, 300 байт на строку, 8 МиБ на файл,
  каждая обрезка помечена маркером; путь канонизируется и не выходит за
  cwd, симлинки не разыменовываются. Под `read_only` доступен наравне с
  `read`; описание `bash` больше не советует shell-grep.
  ← Ревьювер (`--policy read-only`) мог только `read` по точному пути:
  искать вызовы он лез в `bash`, получал отказ и уходил в многоминутные
  рассуждения (R5: 939 с без вердикта, 4× bash ✗; те же bash-попытки в
  A1/E1/E2 — `docs/notes/review-findings-20261104.md`).
  → Поиск по всему репо mark2 — 0.1–0.3 с; преамбула подорожала на
  ≈135 токенов (системный промпт с тулами ≈ 3810 символов). Эффект на
  вердиктах ревью ещё не мерили: нужен повтор сценариев R5/D.

### CLI: `-p -` — промпт из stdin; перевод строки между сообщениями в `-p`
- `mark2 -p -` читает промпт из stdin до EOF (`-` без `-p` — ошибка clap,
  код 2; пустой stdin — `empty prompt`, код 1, до сессии и запроса);
  `scripts/review.sh` всегда отдаёт промпт так, а не одним argv. В `-p`
  текст каждого assistant-сообщения хода начинается с новой строки, если
  предыдущее её не закрыло; дельты внутри сообщения и одиночный ответ —
  байт-в-байт как раньше.
  ← Живое ревью (`docs/notes/review-findings-20261104.md`): фраза модели
  перед тул-коллом склеивалась со следующим сообщением («…test
  module.1. [blocker] …»), а промпт ревьювера шёл одним аргументом — на
  Linux это потолок 128 КиБ. → Промпт в 200 КиБ доходит до сервера модели
  целиком (тест на бинаре с заглушкой сервера); офлайн-контракт обёртки —
  61 проверка, новая ловит промпт в argv. Кап диффа остался 120 КиБ, но
  держит его теперь контекст модели, а не argv; старый `target/release`
  надо пересобрать.

### Бенч: компакция больше не задваивает метрики сессии
- `session_metrics` (`crates/bench/src/metrics.rs`) пропускает серию
  сообщений с `agent_visible = false` сразу за маркером `compacted` — это
  копии, которые компакция дописывает в append-only JSONL; маркеры
  компакций считаются как раньше, формат сессии не тронут.
  ← Каждая компакция пересчитывала уже учтённые ответы, тул-коллы и ошибки:
  сверка stderr ↔ сессия на ноябрьской матрице расходилась в прогоне с
  компакцией. → ctx-v1, flint40 T15 #2: `tool_errors` 2 → 1 (= строк `✗` в
  stderr), `tool_uses` 26 → 13 (= строк `→`+`✗`), `assistant_messages`
  21 → 11; повторы #1/#3 (одна компакция): `tool_uses` 14 → 7. Завышение
  было во всех прогонах с компакцией, не только по ошибкам.

### Бенч: телеметрия обвязки в `results.json` и `report.md`
- Ранер разбирает stderr каждого прогона (`crates/bench/src/telemetry.rs`,
  чистая `parse`) и пишет `runs[].harness`: нуджи `write_churn` /
  `loop_detection`, `coerced`, компакции, тул-коллы с ошибкой; в отчёте —
  раздел «Обвязка» с суммами по модели. Схема аддитивная (`schema_version`
  прежний, старые `results.json` — прочерки). В CLI — новый маркер
  `[agent] compaction: контекст сжат ~X → ~Y токенов` (в stderr `-p` и
  интерактива): раньше компакция в stderr не оставляла следа.
  ← Сенсоры и коэрция включены, а сколько раз они срабатывают на матрице,
  видно только грепом по логам — абляцию нечем сравнить по числам. → Сверка
  на 277 прогонах ноябрьских `bench/results/`: `✗`-строк ровно столько же,
  сколько `tool_errors` в сессии, кроме 5 таймаутов (stderr полнее — сессия
  не дописалась) и 1 прогона с компакцией (сессия считает ошибку дважды:
  скрытые копии сообщений дописываются в JSONL повторно).

### Ревьювер на самом mark2: `scripts/review.sh` (dogfooding)
- Первый агент-пресет поверх ядра — ни одной правки ядра: дифф уходит в
  `mark2 -p --policy read-only`, модель дочитывает файлы тулом `read` и
  заканчивает строкой `VERDICT: approve|needs-work` (exit 0/2). Обёртка
  нумерует строки хунков номерами новой версии файла, повторяет прогон без
  вердикта один раз, режет дифф на 120 КиБ и глушит модель вотчдогом
  (600 с). Офлайн-контракт — 59 проверок под dash/bash/sh с фейковым mark2.
  ← Ревью перед коммитом — гейт, а не агент в цикле (у marmelab авто-ревьювер
  в цикле дал −8пп). → Живые прогоны qwen3.6: все три подсаженных бага
  найдены с точной строкой, безобидные диффы — approve без выдуманных
  находок; нумерация строк ускорила off-by-one со 138 до 26 с (out-токенов
  в 6 раз меньше). Потолок: большие диффы (64 КиБ) модель не осиливает —
  ревьюить по коммитам. Попутно выписаны запросы к ядру: read-only grep,
  промпт из stdin, перевод строки между сообщениями в `-p`, флаг
  температуры (`docs/notes/review-findings-20261104.md`).

### Память агента: `.mark2.memory.md` в системном промпте
- **Файл памяти** — ближайший `.mark2.memory.md` от cwd вверх (тем же обходом,
  что `.mark2.toml`) или `[agent] memory_file` — дописывается последней
  секцией `## Memory` системного промпта: однострочная конвенция и
  содержимое; модель правит файл обычными write/edit, новых тулов ноль. Кап
  4096 байт — обрезка по строке с пометкой и `Event::Warning`; путь и размер
  инъекции — в шапке сессии. Нет файла или он пуст — промпт байт-в-байт
  прежний (тела запросов совпали с замороженным бинарём до памяти).
  ← Агент без памяти между сессиями: каждый запуск начинает с нуля, факты
  проекта, уже сказанные пользователем, приходится повторять в промпте или
  руками дописывать в AGENTS.md. → memory-v1 (5 моделей × 3): T18 «вспомнить
  факт, которого нет нигде, кроме памяти» — 15/15 у всех, включая 4B; T19
  «записать, не испортив файл» — 12/15: ловушка «ответить „запомнил“, не
  записав» поймала qwen9 (0/3), остальные пишут файл корректно. Это же
  первый отчёт с секцией «Обвязка»: нулевые срабатывания контролей на
  простых задачах — ожидаемая база.

### Контроль процесса: write-churn сенсор, коэрция аргументов, абляция
- **Write-churn сенсор** (`[agent] write_churn`): нудж на 3-й подряд записи в
  один файл без единого запуска между ними, жёсткий — на 6-й.
  ← Пилот t17-v1: flint:40b переписал test_chat.py ~10 раз подряд вслепую,
  qwen3.6 — тот же паттерн; существующий детектор зацикливания этого не видит
  (вызовы не идентичны). → Эффект меряется абляцией t17-v3 (ожидается).
- **Коэрция числовых строк** в аргументах тулов (`[agent] arg_coercion`,
  счётчик `coerced N` в статистике): `"60.0"` → 60 без потерь, мусор
  по-прежнему отбивается. ← flint и qwen3.6 стабильно шлют числа строками,
  десятки отбитых вызовов за сессию (flint на T17: tool error rate 33%).
  → Попутно найден баг ядра: число `60.0` проходило JSON Schema, но роняло
  десериализацию в u64.
- **`--agent-override 'key = value'`** в ранере: абляционные прогоны
  (той же матрицей с выключенной фичей), overrides пишутся в results.json и
  шапку отчёта. ← Методология: менять одну часть харнеса за раз и измерять
  вклад каждой; бенч — телеметрия обвязки.
- **`edit_strategy` per-model в матрице**: flint40 → whole_file.
  ← На длинных сессиях flint роняет поля search/replace-edit и спасается
  только перезаписью целиком (наблюдение T17 и чат-демо).
