Build a small multi-user chat in the current working directory: a Python backend `server.py` on aiohttp, a plain JavaScript frontend in `static/index.html`, `static/app.js` and `static/style.css`, and an automated test `test_chat.py`; a checker will start your server, talk to it over WebSocket and drive the page in a headless browser like a real user (typing and clicking), so follow this contract exactly. The server is started as `python3 server.py` from the working directory and must keep running until it is killed; it listens on the port from the `PORT` environment variable, default `8765`, on `0.0.0.0` or `127.0.0.1` (the checker connects to `127.0.0.1`), `GET /` returns `static/index.html`, every file in `static/` is also served at `/static/<name>`, `index.html` loads `/static/style.css` and `/static/app.js` from there, and the WebSocket endpoint is `/ws` on the same port. Every WebSocket message is a text frame holding one JSON object: a client sends `{"type": "join", "nick": "<nick>"}` and `{"type": "message", "text": "<text>"}`, and a client that is connected but has not joined gets no broadcasts and its `message` frames are ignored. The server sends `{"type": "history", "messages": [...]}` only to the client that joined, right after its `join`, with the last 50 chat messages, oldest first, each in the `message` form below (system notices are not part of the history); it sends `{"type": "system", "text": "..."}` to every joined client when a client joins and when a joined client leaves (its WebSocket closes), with a text that names the nick, e.g. `alice joined`, `alice left` (whether the joining client also receives its own join notice is up to you); and when a joined client sends a message it broadcasts `{"type": "message", "nick": "...", "text": "...", "ts": <number>}` to every joined client, the sender included, where `nick` is the sender's nick and `ts` is the server time in Unix milliseconds. `static/index.html` has elements with exactly these ids: `nick` (text input), `join-btn` (button), `msg` (text input), `send-btn` (button) and `messages` (the chat feed), and there is no auto-join: loading the page must never send `join` by itself, not even with a default or remembered nick, the user joins only by acting, and until then `#nick` and `#join-btn` are visible and enabled and `#messages` is empty (no placeholder text). Clicking `#join-btn` joins with the nick typed into `#nick`, and pressing Enter in `#nick` does the same; after joining, `#msg` and `#send-btn` are visible and enabled (before joining they may be hidden or disabled), and pressing Enter in `#msg` or clicking `#send-btn` sends the typed text as a message. On join `#messages` shows the received history, after that every incoming `message` and `system` notice is appended to `#messages` with its text visible, and a message is shown when its broadcast comes back from the server (the sender receives its own broadcast too); the page may open the WebSocket on load or when the user joins, and it is plain JavaScript with no frameworks, no build step and nothing loaded from the internet, because the checker's browser can reach only your server. Write your own automated test `test_chat.py` and ship it with the code: it runs as `python3 test_chat.py` from the working directory, needs nothing already running and finishes within 60 seconds; it starts `server.py` itself as a subprocess (use `sys.executable`) with `PORT` set to a free port it picks, waits until the server accepts connections, and stops the server at the end, also when a check fails; it checks the protocol with real WebSocket clients (join and history, broadcast between two clients, join and leave notices, history for a newcomer), and it exits with status 0 only if every check passed, non-zero otherwise. `python3` on your PATH has aiohttp available and is the same Python the checker uses to run `server.py` and `test_chat.py`, so there is nothing to install: do not install packages globally; you may start the server and run your test while you work, and stop the servers you started before you finish, each by the PID of the process you launched — never by matching names with pkill or killall: other processes on this machine are not yours.
