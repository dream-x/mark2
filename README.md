# mark2

Минимальный agent harness на Rust для **локальных моделей** — llama.cpp (`llama-server`), ollama, LM Studio и любого OpenAI-совместимого API.

Ядро-библиотека + headless CLI. Модель стохастическая — обвязка детерминированная: цикл, тулы со строгой валидацией, permission-гейт, компакция контекста, append-only сессии. Философия — «LLM, цикл и достаточно токенов»: 4 тула, системный промпт вместе со схемами тулов ≈ 1000 токенов, ничего лишнего.

## Статус

**Фаза 1 (MVP) завершена.** Агент решает реальные мини-задачи на локальных моделях (проверено на qwen3.5:9b, gemma4, qwen3.8:27b по сети): стримит вывод, вызывает тулы, чинит собственные ошибки аргументов, пишет сессию, корректно прерывается. 260+ юнит-тестов, живые e2e-тесты. Известные ограничения — в `docs/notes/e2e-findings-20260824.md`.

## Быстрый старт

```sh
cargo build --release

# против ollama
./target/release/mark2 -p --yolo \
  --base-url http://localhost:11434/v1 \
  --model qwen3.5:9b \
  "создай файл hello.txt с содержимым: привет"

# против llama-server (запускать его с --jinja для нативных tool calls)
llama-server --jinja -m model.gguf --port 8081 &
./target/release/mark2 --base-url http://localhost:8081/v1 --model local "поправь баг в main.py"
```

Без `-p` — интерактивный режим: стрим текста, статус тул-коллов (`→ write {...}` / `✓`), подтверждения `y/N` для мутирующих тулов, Ctrl+C прерывает ход. С `-p` — только ответ модели в stdout (exit 0 — успех, 1 — ошибка, 130 — прервано).

## Конфиг

Слои по возрастанию приоритета: `~/.config/mark2/config.toml` → ближайший `./.mark2.toml` (поиск от cwd вверх) → флаги CLI.

```toml
[provider]
base_url = "http://localhost:11434/v1"
# api_key_env = "OPENROUTER_API_KEY"
# cache_prompt = true      # диалект llama-server: KV-кэш префикса
# slot_id = 0              # пин слота llama-server на сессию

[agent]
model = "qwen3.5:9b"
policy = "ask_writes"      # yolo | ask_writes | read_only
# max_turns = 50
# arg_coercion = false     # не приводить "60" → 60 в аргументах тулов (абляция)
# memory_file = "notes/memory.md"  # вместо ближайшего .mark2.memory.md (от директории конфига)

[models."qwen3.5"]         # матчится по подстроке id модели
context_limit = 32768      # включает проактивную компакцию (порог 0.8)
# edit_strategy = "whole_file"  # для слабых моделей вместо search_replace
```

## Тулы

`bash` (timeout, обрезка вывода, kill process group), `read`, `write`, `edit` (exact search/replace; для слабых моделей — режим whole-file). Аргументы валидируются JSON Schema; невалидные — возвращаются модели текстом ошибки (retry-with-error), обрезанный JSON проходит через repair. До валидации числа и булевы, присланные строками (`"timeout_seconds": "60.0"`), приводятся к типу схемы без потерь; сколько вызовов так спасено — `coerced N` в итоговой строке stderr.

## Память

Файл `.mark2.memory.md` — ближайший от cwd вверх (как `.mark2.toml`; конфиг и память ищутся каждый по своему ближайшему) или `[agent] memory_file` — при старте сессии дописывается в конец системного промпта секцией `## Memory`: одна строка конвенции («попросили запомнить — обнови этот файл через write/edit, коротко, только факты») и содержимое. Модель правит его обычными тулами — новых тулов нет.

Включается созданием **непустого** файла: `echo '# Memory' > .mark2.memory.md`. Нет файла или он пуст — промпт байт-в-байт прежний, ни одного токена налога; поэтому голый `touch` память не включает, а конвенцию модель видит только при существующем файле. В промпт уходит максимум 4096 байт: длиннее — обрезка по границе строки с пометкой `[memory truncated: N of M bytes shown]` и `warning:` в stderr, сам файл не трогается. Компакция системный промпт не трогает — память её переживает; путь и размер инъекции пишутся в шапку сессии (`meta.memory`). Меряется задачами бенча T18 (вспомнить) и T19 (записать).

## Сессии

Append-only JSONL в `~/.mark2/sessions/YYYY/MM/DD/*.jsonl`: meta, все сообщения (включая скрытые компакцией — с флагами видимости), маркеры ходов, компакции. Формат сессии = формат для эвалов и бенчмарка.

## Бенчмарк

Протокол: 3 повтора, temperature 0, прогрев, свежая tmp-песочница на прогон. Детали — [bench/STRATEGY.md](bench/STRATEGY.md), сырые результаты и медианы — `bench/results/`.

## Ревью

`scripts/review.sh` — код-ревьювер на самом mark2: локальная модель под `--policy read-only` получает дифф и инструкцию `prompts/review.md`, при нехватке контекста дочитывает файлы репо тулом `read` и заканчивает ответ строкой `VERDICT: approve` или `VERDICT: needs-work` (exit 0 / 2; 1 — ошибка запуска или нет вердикта). Без аргументов ревьюит незакоммиченное (`git diff HEAD`), `--staged` — индекс, `HEAD~3` — последние три коммита, `-` — дифф из stdin (для CI).

Модель по умолчанию — `qwen3.6:35b-a3b-coding` через ollama на `localhost:11434`; переопределяется через `MARK2_REVIEW_MODEL`, `MARK2_REVIEW_BASE_URL`, `MARK2_REVIEW_BIN`, `MARK2_REVIEW_MAX_DIFF_BYTES` (дифф больше 120 КиБ обрезается с пометкой). Офлайн-тесты обёртки — `sh scripts/test-review.sh`, наблюдения с живых прогонов — `docs/notes/review-findings-20261104.md`.

## Роадмап

- **Фаза 2 — надёжность на локалках**: финальный ответ из reasoning-канала, замер KV-кэша, grammar-constrained args, toolshim для моделей без tool calling, бенчмарк
- **Фаза 3 — контур верификации**: post-edit сенсор (диагностика после правок — модели), хуки, resume, steering, инкрементальная суммаризация
- **Фаза 4 — экосистема**: MCP-клиент, Anthropic-провайдер, ACP-адаптер (Zed/JetBrains/neovim как фронтенды)
- **Фаза 5 — изоляция**: песочница (Seatbelt/Landlock), субагенты, TUI
