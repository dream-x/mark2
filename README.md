# mark2

Минимальный agent harness на Rust для **локальных моделей** — llama.cpp (`llama-server`), ollama, LM Studio и любого OpenAI-совместимого API.

Ядро-библиотека + headless CLI. Модель стохастическая — обвязка детерминированная: цикл, тулы со строгой валидацией, permission-гейт, компакция контекста, append-only сессии. Философия — «LLM, цикл и достаточно токенов»: 5 тулов, системный промпт вместе со схемами тулов ≈ 1000 токенов, ничего лишнего.

## Статус

**Фаза 1 (MVP) завершена.** Агент решает реальные мини-задачи на локальных моделях (проверено на qwen3.5:9b, gemma4, qwen3.8:27b по сети): стримит вывод, вызывает тулы, чинит собственные ошибки аргументов, пишет сессию, корректно прерывается. 260+ юнит-тестов, живые e2e-тесты. Известные ограничения — в `docs/notes/e2e-findings-20260824.md`.

## Быстрый старт

```sh
cargo build --release

# против ollama
./target/release/mark2 -p --yolo \
  --base-url http://localhost:11434/v1 \
  --model qwen3.5:9b \
  "создай файл hello.txt с содержимым: привет"

# против llama-server (запускать его с --jinja для нативных tool calls)
llama-server --jinja -m model.gguf --port 8081 &
./target/release/mark2 --base-url http://localhost:8081/v1 --model local "поправь баг в main.py"
```

Без `-p` — интерактивный режим: стрим текста, статус тул-коллов (`→ write {...}` / `✓`), подтверждения `y/N` для мутирующих тулов, Ctrl+C прерывает ход. С `-p` — только ответ модели в stdout (exit 0 — успех, 1 — ошибка, 2 — ошибка в аргументах, 130 — прервано); текст каждого сообщения хода начинается с новой строки, служебное (тул-коллы, предупреждения, токены) — в stderr.

Длинный промпт удобнее подать через stdin: `-` вместо задачи читает её до EOF — без лимита argv (на Linux 128 КиБ на аргумент) и без экранирования. Только вместе с `-p` (интерактиву stdin нужен для подтверждений); пустой stdin — ошибка `empty prompt`.

```sh
./target/release/mark2 -p --model qwen3.5:9b - < task.md
```

## Конфиг

Слои по возрастанию приоритета: `~/.config/mark2/config.toml` → ближайший `./.mark2.toml` (поиск от cwd вверх) → флаги CLI.

```toml
[provider]
base_url = "http://localhost:11434/v1"
# api_key_env = "OPENROUTER_API_KEY"
# cache_prompt = true      # диалект llama-server: KV-кэш префикса
# slot_id = 0              # пин слота llama-server на сессию

[agent]
model = "qwen3.5:9b"
policy = "ask_writes"      # yolo | ask_writes | read_only
# max_turns = 50
# arg_coercion = false     # не приводить "60" → 60 в аргументах тулов (абляция)
# memory_file = "notes/memory.md"  # вместо ближайшего .mark2.memory.md (от директории конфига)

[models."qwen3.5"]         # матчится по подстроке id модели
context_limit = 32768      # включает проактивную компакцию (порог 0.8)
# edit_strategy = "whole_file"  # для слабых моделей вместо search_replace

[web]
# search_base_url = "http://localhost:8888"  # SearXNG для web_search; env MARK2_SEARXNG_URL старше
```

## Тулы

`bash` (timeout, обрезка вывода, kill process group), `read` (только внутри cwd: путь канонизируется, абсолютный наружу, `..` и симлинки наружу отбиваются), `grep` (regex-поиск по файлам внутри cwd, тот же замок: скрытое, бинарные и кэши сборки пропускаются, до 200 совпадений, вывод `путь:строка: текст`; с `files_only: true` regex матчится по путям и тул отдаёт листинг файлов — замена `ls`/glob; доступен и в `--policy read-only`), `write`, `edit` (exact search/replace; для слабых моделей — режим whole-file), `web_fetch` (GET по http(s): HTML → читаемый текст вместо сырой разметки, text/JSON как есть, бинарное — ошибка; таймаут 30 с, до 5 редиректов, тело до 1 МиБ, вывод до 40 000 символов с пометкой об усечении), `web_search` (SearXNG JSON API; регистрируется, только если задан `[web] search_base_url` или `MARK2_SEARXNG_URL`). Содержимое сети приходит модели между маркерами недоверенных данных; сетевые тулы без `--yolo` спрашивают подтверждение, в `read_only` запрещены. Аргументы валидируются JSON Schema; невалидные — возвращаются модели текстом ошибки (retry-with-error), обрезанный JSON проходит через repair. До валидации числа и булевы, присланные строками (`"timeout_seconds": "60.0"`), приводятся к типу схемы без потерь; сколько вызовов так спасено — `coerced N` в итоговой строке stderr.

## Проверка после правки (post-edit сенсор)

```toml
[agent]
post_edit_command = "cargo check -q"   # запускается после каждого успешного write/edit
post_edit_timeout_seconds = 90         # по умолчанию 30, максимум 600
```

Команда выполняется через `sh -c` в рабочей директории агента. Exit 0 — ничего не происходит, даже если команда что-то напечатала: сигнал только об ошибке. Упала или не уложилась в таймаут — модель получает вывод (первые и последние 2000 байт) вместе с результатом записи, в stderr печатается `[agent] post_edit: exit N`. Отмена хода убивает команду. Пустая строка `post_edit_command = ""` выключает сенсор, заданный нижним слоем конфига. В бенче тот же ключ задаётся в `task.toml` задачи и перекрывается `--agent-override`.

## Память

Файл `.mark2.memory.md` — ближайший от cwd вверх (как `.mark2.toml`; конфиг и память ищутся каждый по своему ближайшему) или `[agent] memory_file` — при старте сессии дописывается в конец системного промпта секцией `## Memory`: одна строка конвенции («попросили запомнить — обнови этот файл через write/edit, коротко, только факты») и содержимое. Модель правит его обычными тулами — новых тулов нет.

Включается созданием **непустого** файла: `echo '# Memory' > .mark2.memory.md`. Нет файла или он пуст — промпт байт-в-байт прежний, ни одного токена налога; поэтому голый `touch` память не включает, а конвенцию модель видит только при существующем файле. В промпт уходит максимум 4096 байт: длиннее — обрезка по границе строки с пометкой `[memory truncated: N of M bytes shown]` и `warning:` в stderr, сам файл не трогается. Компакция системный промпт не трогает — память её переживает; путь и размер инъекции пишутся в шапку сессии (`meta.memory`). Меряется задачами бенча T18 (вспомнить) и T19 (записать): memory-v1 — T18 15/15 у всех пяти моделей вплоть до 4B, T19 12/15 — ловушку «ответить „запомнил“, не записав в файл» провалил только qwen3.5:9b.

## Сессии

Append-only JSONL в `~/.mark2/sessions/YYYY/MM/DD/*.jsonl`: meta, все сообщения (включая скрытые компакцией — с флагами видимости), маркеры ходов, компакции. Формат сессии = формат для эвалов и бенчмарка.

## Бенчмарк

## Ревью

`scripts/review.sh` — код-ревьювер на самом mark2: локальная модель под `--policy read-only` получает дифф и инструкцию `prompts/review.md`, при нехватке контекста ищет по репо тулом `grep` (в том числе файлы по имени — `files_only`) и дочитывает файлы тулом `read`, а заканчивает ответ строкой `VERDICT: approve` или `VERDICT: needs-work` (exit 0 / 2; 1 — ошибка запуска или нет вердикта). Без аргументов ревьюит незакоммиченное (`git diff HEAD`), `--staged` — индекс, `HEAD~3` — последние три коммита, `-` — дифф из stdin (для CI).

Модель по умолчанию — `qwen3.6:35b-a3b-coding` через ollama на `localhost:11434`; переопределяется через `MARK2_REVIEW_MODEL`, `MARK2_REVIEW_TEMPERATURE` (по умолчанию 0 — самый воспроизводимый вердикт; уходит в `mark2 --temperature` поверх любого конфига), `MARK2_REVIEW_BASE_URL`, `MARK2_REVIEW_BIN`, `MARK2_REVIEW_MAX_DIFF_BYTES` (дифф больше 120 КиБ ≈ 35–40k токенов обрезается с пометкой: дальше модель теряет начало промпта), `MARK2_REVIEW_TIMEOUT_SECS` (10 минут на прогон). Рабочий размер — сфокусированный дифф в несколько файлов: на больших и «контекстных» диффах модель уходит в многоминутные рассуждения. Промпт уходит в mark2 через stdin (`-p -`), поэтому лимита argv у обёртки нет; собранный раньше `target/release/mark2` этого не умеет — пересобери. Офлайн-тесты обёртки — `sh scripts/test-review.sh`, наблюдения с живых прогонов — `docs/notes/review-findings-20261104.md`.

## Роадмап

- **Фаза 2 — надёжность на локалках**: финальный ответ из reasoning-канала, замер KV-кэша, grammar-constrained args, toolshim для моделей без tool calling, бенчмарк
- **Фаза 3 — контур верификации**: post-edit сенсор (диагностика после правок — модели), хуки, resume, steering, инкрементальная суммаризация
- **Фаза 4 — экосистема**: MCP-клиент, Anthropic-провайдер, ACP-адаптер (Zed/JetBrains/neovim как фронтенды)
- **Фаза 5 — изоляция**: песочница (Seatbelt/Landlock), субагенты, TUI
