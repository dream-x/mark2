# E2E против живых локалок — находки (2026-08-24)

Приёмка фазы 1 (Task 9 плана `docs/plans/20260824-rust-agent-harness.md`).
Стенд: macOS (Apple Silicon), **ollama 0.32.15** на `http://localhost:11434/v1`,
mark2 из ветки `main` (debug-сборка), режим `-p --yolo`, сессии пишутся.

Команда прогона:

```sh
cargo run -q -p mark2-cli -- -p --yolo \
  --base-url http://localhost:11434/v1 --model qwen3.5:9b -C <dir> "<задача>"
```

## Проблемы (вход для фазы 2)

### P1 — финальный ответ теряется, если модель положила его в `reasoning`

Прогон (a): последнее сообщение хода — `[{"type":"thinking","text":"The file has
been created successfully…"}]`, текстового блока нет вообще. `-p` печатает в
stdout **пустоту** и выходит с кодом 0. Для headless-режима это худший из
возможных исходов: скрипт получает успешный код и ноль байт.

Что делать: если ход завершается сообщением без текста и без тул-коллов —
использовать thinking как ответ (или, минимум, писать на stderr «модель не дала
текстового ответа»). Заодно перестать класть в сообщение пустые `thinking`-блоки.

### P1 — нет контура верификации, модели тратят на него итерации сами

Прогон (d): половина хода — попытки проверить правку шеллом наугад
(`cargo test` без `Cargo.toml`, `rustc` без `--test`). Прогон (c′): gemma4 сама
запустила `python stats.py` и на этом успокоилась. Модель хочет обратной связи и
будет её добывать любой ценой; на локалке каждая лишняя итерация — это ещё один
проход по всему контексту.

Что делать: post-edit сенсор из фазы 3 (конфигурируемая команда диагностики,
вывод → модели) стоит поднять в приоритете — он не «улучшение качества», а
экономия итераций.

### P2 — тело HTTP-ошибки печатается целиком

Дефолтный `base_url` — `http://localhost:8080/v1`, и если там сидит посторонний
сервер (см. «Грабли»), пользователь получает **58 строк HTML** в stderr:

```
WARN mark2_providers::openai_compat: повтор запроса к провайдеру attempt=1 delay_ms=250
     error=HTTP 501: <!DOCTYPE HTML>
     <html lang="en">
     …
```

Что делать: обрезать тело ошибки (≈500 символов), а при `content-type: text/html`
добавлять подсказку «похоже, `base_url` указывает не на OpenAI-совместимый API».

### P2 — ретраим то, что ретраить бессмысленно

501 Not Implemented (чужой сервер) и 500 «модель не грузится» (прогон c)
ретраились по два раза с бэкоффом. Ни то, ни другое от повтора не пройдёт.

Что делать: ретраить 408/429/502/503/504 и сетевые обрывы; 500/501 от локального
сервера — сразу наверх (или один повтор вместо двух).

### P2 — модель не доверяет рабочей директории

И gemma4, и qwen сами подставляют `cd <абсолютный путь> && …` в `bash`, хотя тул
и так исполняется в cwd. Это лишние токены и источник ошибок при переносе задачи.

Что делать: явно назвать cwd в системном промпте или в описании тула `bash`
(«команда исполняется в `<cwd>`»). Правка на одну строку промпта.

### P2 — по prompt-кэшу нет измерений

ollama не отдаёт `prompt_tokens_details.cached_tokens`, поле `cache_read_tokens`
в `Usage` всегда пустое, и в сводке `tokens: in … / out …` кэш не виден. Замер
попадания в KV-кэш (пункт фазы 2) придётся делать на llama-server через
`timings` — парсер для них уже есть.

Размер стабильного префикса (снят с реального запроса): системный промпт —
**891 байт**, схемы четырёх тулов — **2821 байт**, весь первый запрос — 3755
байт ≈ **~1000 токенов**. Бюджет плана («≤1000 токенов промпт + тулы»)
выдержан; на тривиальной задаче (a) это ~2400 входных токенов за ход.

### P3 — `-p` молчит о том, что делал агент

При пустом финальном тексте (P1) в выводе не остаётся вообще ничего: ни списка
тулов, ни файлов. Кандидат — короткая сводка выполненных тулов в stderr.

### P3 — лишний `ls` перед `read`

gemma4 тратит первую итерацию на осмотр каталога. Идея: короткий листинг cwd в
системном промпте (внутри сессии он стабилен и кэш не ломает).

## Грабли стенда

- **Порт 8080 занят посторонним сервером.** Дефолт `DEFAULT_BASE_URL =
  http://localhost:8080/v1` рассчитан на llama-server, но на этой машине по 8080
  отвечает чужой веб-сервер: приходит HTTP 501 с HTML-страницей `Error response`.
  Симптом — простыня HTML вместо ответа модели. Всегда задавай `--base-url` явно
  или пропиши его в `~/.config/mark2/config.toml`.
- **ollama слушает 11434**, OpenAI-совместимый префикс — `/v1` (не `/api`).
- **gpt-oss:20b в этой инсталляции битый**: `tensor "blk.0.ffn_down_exps.weight"
  size overflow` на любой запрос, включая голый `curl`. Для сравнения моделей
  бери `gemma4:latest`; gpt-oss нужно перекачать (`ollama pull gpt-oss:20b`).
- **qwen3.5:9b поднимается с контекстом 262 144** (`ollama ps`), так что на
  мини-задачах компакция не триггерится в принципе. Чтобы проверить её на живой
  модели, нужен маленький `context_limit` в `[models."…"]`.
- **qwen3.5 через ollama шлёт рассуждения в поле `reasoning`**, а llama-server —
  в `reasoning_content`; оба варианта провайдер уже понимает.
- Ignored-тесты запускаются параллельно (по числу ядер). Для тяжёлых моделей —
  `-- --ignored --test-threads=1`.

## Вердикт по фазе 1

Критерий MVP выполнен: агент на локальной модели решает «создай файл» и
«найди и почини баг», ходит тулами `read`/`edit`/`write`/`bash`, стримит вывод,
уважает политику доступа, пишет сессию в JSONL и корректно завершается с
понятным кодом возврата на ошибке провайдера. Блокеров нет; на вход фазе 2
уходят P1-проблемы выше.
