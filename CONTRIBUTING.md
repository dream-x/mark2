# Контрибьюторам

## Требования

- Rust stable ≥ 1.98 (edition 2024)
- Для живых e2e — любой OpenAI-совместимый сервер с моделью, умеющей tool calling (ollama с qwen3.5:9b достаточно)

## Команды

```sh
cargo build                                            # сборка
cargo test                                             # все юнит-тесты
cargo fmt --check && cargo clippy --all-targets -- -D warnings   # обязательный гейт
cargo test -p mark2-cli --test e2e_local -- --ignored  # живые e2e (нужен локальный сервер)
cargo run -p mark2-cli -- --help                       # CLI
```

PR/коммит не считается готовым, пока `fmt + clippy -D warnings + test` не зелёные. Warnings — это ошибки.

## Правила

1. **Тесты обязательны в том же изменении.** Новый код — новые тесты (успех и ошибки), изменённое поведение — обновлённые тесты. Агентную логику тестируй через `MockProvider` (примеры в `crates/core/src/agent.rs`), wire-парсинг — фикстурами реальных чанков (примеры в `crates/providers/src/openai_compat.rs`).
2. **Не ломай инварианты** из [ARCHITECTURE.md](ARCHITECTURE.md#ключевые-инварианты-не-ломать): append-only история, байт-стабильная сериализация, «глупый» провайдер, ядро без UI, парные tool_result, толерантный serde, один примитив отмены. На большинство есть тесты — они упадут; отсутствие теста не делает поломку допустимой.
3. **Wire-имена стабильны.** serde-теги `Event`/`Op`/`SessionItem`/`ContentBlock` — это формат сессий на диске и будущих фронтендов. Добавлять варианты можно, переименовывать/удалять — нельзя. Потребители обязаны иметь wildcard-ветку на незнакомые варианты.
4. **Держи ядро маленьким.** Новая функциональность — это либо новый `Tool`, либо новый `Provider`, либо потребитель Op/Event. В цикл агента код добавляется в последнюю очередь и только если ему точно там место (см. анти-примеры в ARCHITECTURE: codex/goose с их годфайлами).
5. **Бюджет промпта.** Системный промпт + схемы тулов ≤ ~1000 токенов. Описания тулов и полей — короткий английский (их читает модель). Есть тест на размер.
6. **Русский в доках и комментариях, английский — в том, что читает модель** (промпт, описания схем, сообщения об ошибках тулов).

## Как добавить тул

1. Файл в `crates/core/src/tools/`, input-структура с `derive(JsonSchema)` и описаниями полей.
2. Реализуй `trait Tool` (`name`, `description`, `input_schema` через `input_schema_for::<T>()`, `execute`).
3. Ошибки — человекочитаемые и **инструктивные**: их читает модель и чинит вызов («expected …, got …; fix and call again»).
4. Мутирующий тул — добавь в `MUTATING_TOOLS` (`permission.rs`).
5. Регистрация в `ToolRegistry::with_defaults` (порядок фиксирован — не переставляй существующие).
6. Тесты: happy-path, ошибки, отказ валидации, поведение при cancel/timeout, если применимо.

## Как добавить провайдер

Реализуй `mark2_core::Provider` в `crates/providers/`: один метод `stream()`, отдающий `StreamChunk`-и и финальный `Complete{message, usage}`. Wire-типы — толерантные (`#[serde(default)]`), маппинг переполнения контекста — в `ProviderError::ContextLengthExceeded`, ретраи только до начала стрима. Сериализация запроса детерминированная. Смотри `openai_compat.rs` как образец, тесты — на инлайн-фикстурах реальных ответов сервера.

## Процесс

- Крупные изменения идут через план в `docs/plans/` (формат — см. выполненные в `docs/plans/completed/`); прогресс отмечается чекбоксами, выполненный план переезжает в `completed/`.
- Коммиты — conventional-стиль: `feat(core): …`, `fix(providers): …`, `docs: …`, `test: …`.
- Находки с живых прогонов (баги моделей, грабли серверов) фиксируй в `docs/notes/` — это вход для следующих фаз.
- AI-агентам: инструкции в `AGENTS.md`; этот файл и ARCHITECTURE.md — тоже для вас.
